# 断言与用例

## 把业务预期写成断言

每次发送都会检查 RPC 是否成功。还可以在「断言」页签添加一条响应字段断言和一个 RPC 耗时上限，两者可以同时使用。

| 响应片段 | JSON Pointer | JSON 期望值 |
| --- | --- | --- |
| `{"user":{"id":"42"}}` | `/user/id` | `"42"` |
| `{"items":[{"active":true}]}` | `/items/0/active` | `true` |
| `{"count":2}` | 留空，比较整个响应 | `{"count":2}` |

期望值采用 JSON 类型，字符串要带双引号。字段名中的斜杠写为 `~1`，波浪号写为 `~0`。耗时上限单位为毫秒，比较结果中的 RPC 耗时。总耗时还包含 schema 编译。

## 保存和回放

发送前勾选「保存为用例」并填写名称。本机 Buf 工作区的 `.ilabrat/history/<UUID>.json`（SSH 和单文件模式位于 DSH 用户的 `.ilabrat/cases` 下） 会记录请求、断言和此次结果。失败样本也可以保留。

- **单条复测**：在「用例」中点名称，确认恢复的地址、方法和请求，按需补填 Metadata 后发送。
- **批量回归**：勾选用例再点击「运行选中」，按勾选顺序执行。展开每条结果可看失败详情。需要凭据的用例若缺少 Metadata 值，该条会报告失败。
- **分享请求**：点击「导出用例」，对方可以用「导入用例」恢复请求与断言，检查目标地址后发送。导出的文件与历史记录格式各自独立。

Metadata 只保存键名，回放时需重新填写值。请求体和响应可能包含业务数据，分享或提交用例前请检查内容。
