# 从 Windows 经 Linux 发出第一条 gRPC 请求

假设 DSH 装在 Windows，测试服务只接受 Linux 开发机所在网段的连接。你手上有服务地址和开发机上的 Proto 文件。

1. 打开侧栏 **Ilabrat**。在「请求来源」点「添加 SSH」，填写开发机地址、端口、用户名和来源名称，选择密码或 SSH agent。点击「读取主机指纹」，与开发机管理员提供的 SHA256 指纹核对，点击「信任并保存」。以后直接选择这个来源。需要从 Windows 直连时，选「本机 · DSH」。
2. 在「协议来源」选「Proto 文件」，点击「浏览文件…」。浏览器显示当前来源机器的目录；可以逐级进入目录，也可以输入目录跳转。点击文件就会解析。项目有多个 Buf 模块或 BSR 依赖时，选「Buf 工作区」并选择含 `buf.yaml` 的目录。
3. 在「目标环境」填服务的 `host:port`，选择 TLS 或明文 h2c，点击「保存目标」起名。同一个目标可以从不同来源调用。SSH 模式下，`localhost` 指 Linux 开发机。
4. 从 Package、Service、Method 依次选择接口。按生成的字段填值，可以增加数组项、map 键值和切换 oneof。枚举和布尔值用下拉选项，64 位整数按字符串保留精度。「JSON」可以编辑完整请求，包括 Any 的具体类型。空消息可直接发送。
5. 需要鉴权时在 Metadata 页签填字符串键值对。在「断言」中可填写响应字段路径、期望值或 RPC 耗时上限。「发送请求」会从选定来源调用服务，并显示响应和检查结果。
6. 点「保存模板」记录常用的来源、目标、协议路径、接口、已填写的请求和断言。下次打开配置模板时会重新读取协议，再由你点击发送。SSH 密码留在 DSH 宿主的凭据存储里，Metadata 的值需要重新填写。需要留存响应或批量重跑时，使用[回归用例](Test-cases.md)。
